# Data Source Routing — 候选素材的触发与路由协议

被 cheat-seed / cheat-trends 引用。规定**何时**要外部素材、**从哪来**、**没有时怎么办**。

> ⚠️ **本仓库不内置任何第三方热点抓取源。**
> 不附带 aihot / 微博热搜 / 知乎热榜 / TrendRadar 等接入实现或说明。
> 唯一内置来源 = **`manual-paste`（用户手动粘贴）**。
>
> 原因：第三方热点源的**抓取合规与商用授权**边界复杂且会变（平台用户协议、robots、数据授权、著作权），
> 本仓库不代为实现、不代为授权——接入与否、能否商用，由用户自行判断并自负责任。

---

## 核心哲学

> **外部素材是"前置参考"，不是"主菜单"。**
>
> - 用户在**内省**（讲自己的经历 / 思考动机）→ **不要素材**，避免外部信息污染
> - 用户在**找素材**（没想法 / 要批量 / 显式补充候选池）→ **要素材**，走 manual-paste 或用户自建源
> - 用户在**确认 angle**（讲了时事话题）→ **不主动要**，让用户决定要不要把外部信息粘进来

设计目的：保护 cheat-seed 的核心论点——"好内容来自用户的真实经历，AI 不凭空 brainstorm"——同时不让"完全没想法"的新博主卡死。

---

## 触发矩阵（被 cheat-seed Phase 1 引用）

| cheat-seed Mode | 默认要素材？ | 触发条件 |
|---|---|---|
| **Mode A**（用户给了具体经历/topic） | ❌ 默认不要 | 仅当用户讲的本身是时事话题（含产品名/人名/事件名 + 时间词）+ 用户**主动同意** |
| **Mode B**（方向不具体，问"为什么"） | ❌ **永远不要** | 这阶段用户在内省，外部素材是噪音 |
| **Mode C**（完全没想法） | ✅ 默认要 | Mode C 的核心动作就是把素材摆出来 |
| `--batch N` | ✅ 默认要 | 批量 brainstorm 必须有 anchor |
| `/cheat-trends` 显式 | ✅ 要 | 主入口，无需解释 |
| `/cheat-recommend` | ❌ 默认不要 | 已有 pool；除非 pool >7 天没更新 → 提示先补素材 |

## 时事话题判定（Mode A 灰色场景用）

让 Claude 判断，**不写正则白名单**：

| 信号 | 含义 |
|---|---|
| 含**专有名词**（人名 / 产品名 / 事件名） | 强信号——可能是时事 |
| 含**时间词**（"今天" / "刚" / "最近" / "刚刚发生"） | 强信号 |
| 含**结构词**（"对比" / "回应" / "事件"） | 弱信号 |
| 仅含通用名词 + 个人经历词（"我" / "昨天" / "我同事"） | 反信号——是长青个人经历，**不是时事** |

判定结果：
- **强信号** → 询问用户"要不要把这话题你看到的报道 / 舆论**粘几条**给我作参考"（**本仓库不自动抓取**）
- **弱信号 / 模糊** → 不主动询问，直接进 Mode A 深挖
- **反信号** → 100% 不要

跟 [bump-validation-protocol.md](bump-validation-protocol.md) 的"软规则、Claude 判断"哲学一致。

## 素材来源

| 来源 | 说明 |
|---|---|
| **`manual-paste`** | **唯一内置**。询问用户："粘贴你今天的候选 URL / 标题列表（每行一条）" → 解析每行，对 URL 做 WebFetch 补 snippet |
| 用户自建 adapter | 想接自己的源（RSS / 官方开放 API / 自己的榜单）→ 见文末「扩展指南」，**合规与授权由用户自负** |

> 本仓库**不提供**、**不背书**任何第三方热点抓取源的接入说明。

## 失败降级链

```
[cheat-seed Mode C / /cheat-trends 触发要素材]
  ↓
[询问用户粘贴候选 URL/标题]
  ↓
  ├─ 用户粘了 → 解析 + 去重 + 粗打分 → 进流程
  ├─ 用户没得粘 → 走"聊经历"兜底（cheat-seed Phase 2C 三选项）
  └─ 用户自建源可用（如已配）→ 也可用，但其可用性由用户自己保证
```

**关键纪律**：所有失败都**不抛异常**。cheat-seed 永远能跑——区别只是有没有外部素材。

## 成本意识

`manual-paste` 没有 API 调用成本；这里的"成本"是**用户的时间**。判定原则：

| 场景 | 频率 |
|---|---|
| Mode C 触发 | 每次会话最多 1 次（拿到的素材 cache 在内存） |
| Mode A 灰色场景 | 用户同意才问，1 次 |
| `--batch N` | 1 次拿足够候选 |
| 用户连说"再来一批" | 第二次允许，第三次提示"要不要换角度" |

不要在同一会话里反复追问同一批素材——那是浪费用户耐心。

## 与 candidates.md 的关系

素材**最终落到** [candidate-schema.md](candidate-schema.md) 定义的 `candidates.md`：

```
[来源输入] → items
  → 去重（vs candidates.md / predictions/ / .cheat-cache/trends-history.jsonl）
  → 粗打分（cheat-seed 内联 rubric）
  → 写入 candidates.md（带 source 字段标明来源）
```

cheat-seed Mode C 拿到素材后**不**直接进 brainstorm，先入 candidates.md，再让 Claude 从池子里选。这样数据可追溯、可被后续 cheat-recommend 复用。

## 扩展指南（用户 / maintainer）

本仓库**默认不自带任何 trend source**。要接自己的源：

1. 写 `adapters/trend-sources/<name>.md`，按 [candidate-schema.md](candidate-schema.md) 的输出契约描述你的来源
2. 在 `.cheat-state.json` 的 `enabled_trend_sources` 里登记
3. 不需要改 cheat-seed 内部逻辑——按 `enabled_trend_sources` 自动启用
4. CHANGELOG 标 MINOR

⚠️ **合规提醒**：接入任何第三方数据源前，请自行确认该源的**用户协议 / robots / 著作权 / 商用授权**边界。
本仓库不对用户自建源的合法性负责，也不提供任何第三方源的接入说明。
