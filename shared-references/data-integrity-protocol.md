# SuperC 数据复盘唯一真源协议

## 目的

把真实发布记录和预测、草稿、对标资料隔离，避免同一条内容在多个文件中产生互相冲突的数据。

## 允许写入的数据

只有以下内容可以进入 `knowledge_base/数据复盘/`：

- 实际发布过的最终文案；
- 平台、链接、内容 ID、实际发布时间；
- 从平台后台或明确来源取得的真实数据；
- 数据采集时间、来源、状态和更正说明；
- 发布后的复盘结论。

## 不允许写入的数据

- 草稿和计划日期；
- 发布前预测；
- 对标账号数据；
- 尚未验证的推断；
- 把预测区间复制成实际表现；
- 为同一条内容建立多个“终值”文件。

## Upsert 规则

所有写入都必须先执行 `find_existing_record`：

```text
platform_content_id
  > publish_url
  > platform + published_at
  > platform + title + published_date
```

匹配到记录时执行更新（upsert），不得追加重复记录。匹配不到时才创建新记录。

项目提供 `tools/upsert_published_record.py` 作为机器写入入口。新记录使用 `record_id`，后续更新必须复用同一个 `record_id`；人工维护的旧台账继续遵守同样的唯一键规则。

字段更新遵循：

```text
新事实 > 旧临时值
新采集时间和来源必须保留
旧的错误值不进入统计，但更正原因要留在原记录
```

## 覆盖前检查

每次更新后检查：

1. 内容 ID、链接、平台和发布时间是否重复；
2. 同一标题是否被误建成两条；
3. 最终文案是否来自真实发布版本；
4. 阶段数据是否被误标为终值；
5. 该条是否同时出现在待发队列和已发布台账。

发现冲突时，保留真实发布台账作为主记录，其余文件只做引用或标记为失效，不参与统计。

## 下游读取边界

- 账号诊断、复盘和规律提炼：可以读本目录；
- 写稿和选题：只能读取已结案或明确标记为阶段数据的记录，并注明状态；
- 盲评分：禁止读取本目录中的实际数据；
- 对标导入：只能写入 `对标账号/`，不得写入 `数据复盘/`。
